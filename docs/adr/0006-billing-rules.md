# 0006. Правила списания и нулевого баланса

- Статус: предложено, ждёт подтверждения владельца
- Дата: 2026-11-05

## Контекст

Цена ответа известна только после вызовов модели, а баланс не должен уходить в минус. Настройки цен нужны общие, но таблица по правилу проекта обязана иметь `tenant_id` и RLS.

## Решение

- **Баланс — только сумма `ledger`.** Колонка `tenants.balance_kzt` удалена, чтобы не было двух источников правды.
- **Настройки цен** живут в `pricing_settings`: строка внутреннего магазина Satushy действует на всех, строка магазина её заменяет. Читает SECURITY DEFINER-функция `pricing_effective()`, она берёт магазин из `app.tenant_id`, поэтому чужую наценку прочитать нельзя. Нет строк — наценка 3 и `PRICING_KZT_PER_USD`.
- **Два рубежа защиты баланса.** До вызова модели узел `gate` сравнивает баланс со средней ценой последних 20 ответов. При списании под `pg_advisory_xact_lock` сумма ограничена остатком: если ответ оказался дороже, списывается остаток, разницу берёт на себя Satushy.
- **Не списываем:** песочницу, шаблон без вызова модели и ответ, который канал не смог доставить. Ответ `fallback` после проверки цен списываем: модель отработала.
- **При пополнении диалоги с `paused_reason = no_balance` возвращаются боту.** Экрана диалогов пока нет, и без этого покупатели остались бы без ответа навсегда. Диалоги, переданные менеджеру по другим причинам, и лимит в час не трогаем.
- **Telegram владельца** подключается через бота магазина: ссылка `/me/telegram/link` с одноразовым токеном на 10 минут.
- **Группировка неотвеченных:** косинус BGE-M3 не меньше 0,85. На проверочных парах распределения пересекаются (перефразировки 0,71–0,93, разные вопросы 0,44–0,84), порог выбран так, чтобы не склеивать разное: лишняя строка безвредна, общий ответ на разные вопросы вреден.

## Последствия

- Новый магазин стартует с нулевым балансом: на каналах бот отвечает шаблоном, пока нет пополнения. Песочница работает.
- Смена цены действует на будущие ответы; журнал не меняется.
