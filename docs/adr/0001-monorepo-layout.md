# 0001. Монорепозиторий и стек каркаса

- Статус: принято
- Дата: 2026-11-03

## Контекст

MVP — один сервер, один разработчик, три сервиса на двух языках (SPEC.md, «Архитектура и стек»). Нужно, чтобы изменения в API и кабинете шли одним коммитом, а локальный запуск был одной командой.

## Решение

- Один репозиторий: `apps/api`, `apps/ml`, `apps/web`, `infra/`, `docs/`.
- `apps/api` и `apps/ml` — **отдельные** uv-проекты со своими `uv.lock`, без uv workspace: ML-сервис потянет torch и модели, API это не нужно; Docker-образы собираются независимо.
- ML-модели живут в отдельном сервисе, чтобы тяжёлые зависимости и память (~несколько ГБ) не попадали в API и воркеры.
- API и ARQ-воркер — один код и один образ, разные команды запуска.
- Web — npm (pnpm/turbo не нужны при одном JS-пакете).
- Хост-порт Postgres по умолчанию 5433, чтобы не конфликтовать с локальным Postgres.

## Последствия

- Линтеры Python настраиваются в каждом `pyproject.toml` отдельно — небольшое дублирование конфигов.
- Когда появится общий Python-код между api и ml, вернуться к вопросу uv workspace.
