# ADR 0007: как кабинет ходит в API

Статус: принято, 2026-11-05.

## Прокси вместо CORS

Браузер обращается к API через Next (`/api/*`, `/auth/*` → `API_INTERNAL_URL`). Кабинет и API для браузера на одном адресе, поэтому не нужен CORS с cookie, а `SameSite=Lax` и httpOnly работают без исключений. Refresh-cookie выдан на путь `/auth`, поэтому этот путь проксируется отдельно и без префикса `/api`.

Цена: адрес API в `output: standalone` зашивается при сборке (`ARG API_INTERNAL_URL` в Dockerfile), а `proxyTimeout` поднят до 5 минут ради автопроверки бота, которая идёт одним запросом.

## SSE опросом базы

`GET /conversations/stream` раз в 1,5 секунды смотрит `updated_at` диалогов и заявок магазина и шлёт событие «изменилось», клиент сам перечитывает данные. Соединение с базой между опросами не держится.

Отказались от Redis Streams, как в виджете: диалог меняют узлы графа в воркере, вебхуки, пополнение из админки и кабинет, и в каждом месте пришлось бы не забыть опубликовать событие. `updated_at` ставит триггер, поэтому изменение не потеряется. Чтобы так работало, `meter` теперь тоже обновляет `conversations.last_message_at`.

Когда менеджеров станет много, опрос заменим на `LISTEN/NOTIFY` или Redis, контракт события не изменится.

## Стоимость модели не показываем

В ответе диалога нет `llm_calls` и `cost_usd`: из них магазин вычислил бы нашу наценку. В блоке «Как бот нашёл ответ» видны шаги и списанная сумма.
