# 0012. Лендинг отдельно от сервиса, в AWS без серверов

- Статус: принято
- Дата: 2026-11-13

## Контекст

Пока продукт не запущен, наружу нужен только сайт: кто мы, что делаем, форма для заявки. Сервис с кабинетом и API (`apps/api`, `apps/ml`, `apps/web`) публиковать рано, а держать под него серверы и базу — платить за простой. Позиционирование тоже меняется: Satushy — IT-команда, которая делает автоматизацию для бизнеса, а бот-продавец — её главный готовый продукт.

Первая попытка — переписать лендинг заново обычными HTML и CSS в отдельной папке — была отклонена: у существующего лендинга из `apps/web` больше взаимодействий (живой чат, карточки с наведением, бегущие вопросы), и владельцу он нравится больше. Из новой версии оставлена одна идея: ночь, которая на глазах становится утром.

## Решение

- Лендинг остаётся в `apps/web` и собирается в двух режимах из одного компонента `components/landing/landing-page.tsx`:
  - обычная сборка сервиса — как раньше, со входом и демо-кабинетом;
  - `LANDING_ONLY=1` — статическая выгрузка (`output: "export"`) в `apps/web/out`. В этом режиме маршрутами считаются только файлы `*.landing.tsx` (`pageExtensions`), поэтому кабинет, вход и `proxy.ts` в сборку не попадают вообще.
- В режиме отдельного лендинга (`standalone`) вместо входа и демо — кнопки к форме заявки, добавлен раздел «не только боты» и светлая «утренняя» форма в конце. Чат в первом экране отвечает записанными репликами демо-магазина, без обращения к API.
- Кнопку демо-кабинета страница сервиса передаёт в лендинг сама (`demo`), чтобы код демо-входа не попадал в сборку лендинга.
- Раздел «Пока магазин закрыт» (`night-shift.tsx`) проигрывает ночь: часы идут от 23:41 до 07:00, события появляются по времени, фон светлеет к рассвету.
- Хостинг — закрытый бакет S3 за CloudFront (доступ только через Origin Access Control). Серверов и базы нет; при малом трафике это укладывается в бесплатные лимиты AWS.
- Форма шлёт `POST /api/lead` на тот же домен. CloudFront отдаёт этот путь в API Gateway (HTTP API, ограничение 2 запроса в секунду), тот вызывает Lambda `apps/landing/lambda/handler.py`.
- Функция проверяет заявку, кладёт её JSON-файлом в отдельный закрытый бакет и публикует в тему SNS, подписанную на почту владельца. Заявка считается принятой, если сработало хотя бы одно из двух: письмо может не дойти, файл останется.
- Запросы мимо CloudFront функция отклоняет: CloudFront добавляет секретный заголовок, значение хранится параметром стека.
- Инфраструктура описана в `infra/landing/stack.yaml` (CloudFormation), разворачивается `make landing-deploy`. Адрес для заявок передаётся переменной `LEADS_EMAIL` при первом запуске и в репозиторий не попадает.

## Последствия

- Один лендинг на два случая: правка дизайна видна и на сайте команды, и в сервисе. Отличия собраны в ветках `standalone`.
- Тест `apps/landing/tests/site.test.mjs` проверяет собранный сайт: выгружена только главная, нет ссылок на вход и кабинет, нет кода демо-входа, форма и разделы на месте.
- CSP разрешает встроенные скрипты и стили: статическая сборка Next.js кладёт данные страницы в `<script>`. Чужие источники запрещены.
- В сборке лендинга остаётся код запроса к демо-чату (`/demo/chat`), но он не вызывается: чат работает в режиме `offline`.
- Текст заявки и контакты в логи не пишутся — только номер заявки и итог (проверяется тестом).
- Тема письма в SNS — латиницей: SNS принимает в теме только ASCII. В каждом письме SNS добавляет ссылку «отписаться»; нажатие по ней отключает письма, заявки при этом продолжают сохраняться в бакете.
- Свой домен подключается позже: сертификат ACM в `us-east-1` и `Aliases` у раздачи CloudFront. Форма при этом не меняется, потому что обращается к своему же домену.
- Удаление стека убирает всё, кроме бакета с заявками (`DeletionPolicy: Retain`).
