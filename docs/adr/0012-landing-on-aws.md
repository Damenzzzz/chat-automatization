# 0012. Лендинг команды отдельно от сервиса, в AWS без серверов

- Статус: принято
- Дата: 2026-11-13

## Контекст

Пока продукт не запущен, наружу нужен только сайт: кто мы, что делаем, форма для заявки. Сервис с кабинетом и API (`apps/api`, `apps/ml`, `apps/web`) публиковать рано, а держать под него серверы и базу — платить за простой. Позиционирование тоже меняется: Satushy — IT-команда, которая делает автоматизацию для бизнеса, а бот-продавец — её главный готовый продукт.

Лендинг внутри `apps/web` завязан на кабинет: ссылки на вход и демо, общий `proxy.ts`, сборка всего приложения. Отдать его отдельно от API нельзя без условной сборки.

## Решение

- Лендинг — отдельное приложение `apps/landing`: обычные HTML, CSS и один скрипт без фреймворка и без шага компиляции. `build.mjs` копирует `site/` в `dist/` и добавляет хеш в имена стилей и скрипта.
- Хостинг — закрытый бакет S3 за CloudFront (доступ только через Origin Access Control). Серверов и базы нет; при малом трафике это укладывается в бесплатные лимиты AWS.
- Форма шлёт `POST /api/lead` на тот же домен. CloudFront отдаёт этот путь в API Gateway (HTTP API, ограничение 2 запроса в секунду), тот вызывает Lambda `apps/landing/lambda/handler.py`.
- Функция проверяет заявку, кладёт её JSON-файлом в отдельный закрытый бакет и публикует в тему SNS, подписанную на почту владельца. Заявка считается принятой, если сработало хотя бы одно из двух: письмо может не дойти, файл останется.
- Запросы мимо CloudFront функция отклоняет: CloudFront добавляет секретный заголовок, значение хранится параметром стека.
- Вся инфраструктура описана в `infra/landing/stack.yaml` (CloudFormation), разворачивается `make landing-deploy`. Адрес для заявок передаётся переменной `LEADS_EMAIL` при первом запуске и в репозиторий не попадает.
- Заголовки безопасности, включая строгий CSP без встроенных стилей и скриптов, выставляет CloudFront.

## Последствия

- Сайт не зависит от API: кабинет, вход и демо на нём не упоминаются, это проверяет тест `apps/landing/tests/site.test.mjs`.
- Тексты лендинга правятся прямо в `apps/landing/site/index.html`; общих компонентов с `apps/web` нет, фирменные цвета и шрифты продублированы.
- Текст заявки и контакты в логи не пишутся — только номер заявки и итог (проверяется тестом).
- Тема письма в SNS — латиницей: SNS принимает в теме только ASCII. В каждом письме SNS добавляет ссылку «отписаться»; нажатие по ней отключает письма, заявки при этом продолжают сохраняться в бакете.
- Свой домен подключается позже: сертификат ACM в `us-east-1` и `Aliases` у раздачи CloudFront. Форма при этом не меняется, потому что обращается к своему же домену.
- Удаление стека убирает всё, кроме бакета с заявками (`DeletionPolicy: Retain`).
